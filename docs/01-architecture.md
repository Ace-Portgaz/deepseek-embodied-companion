# 架构与能力边界

## 分工

| 层 | 实现 | 输入 → 输出 |
| --- | --- | --- |
| 身体 | Android 11 / LineageOS 18.1 + RemBody | 摄像头、麦克风、屏幕、扬声器、传感器 |
| 视觉反射 | Camera2 + MediaPipe + ObservationPolicy | 图像 → 跟随坐标、有限动作事件 |
| 形象 | 本地 WebView + Live2D 渲染桥 | 坐标、表情、语音能量 → 模型参数 |
| 对话大脑 | DeepSeek API | 用户文本、近期事件、记忆、人设 → 日语回答 |
| 听觉 | 火山流式 ASR | 16 kHz 单声道音频 → 日语文本 |
| 发声 | GPT-SoVITS v2ProPlus → Genie ONNX | 日语文本 → 参考音色 PCM；失败时回退火山 |
| 连续性 | 服务端身份别名 + RemMemory | 手机与 ESP32 映射到同一摘要记忆 |

眼睛跟随不等待 DeepSeek：每个可用视觉帧在本地处理、平滑并更新角色。点头和挥手也由本地策略判断。DeepSeek 收到的是“几秒前挥手”的有限事件描述，不接收照片，也不直接控制每一帧眼睛坐标。

手机的身体发生迁移时，服务端为新设备生成独立凭据，再把它关联到同一记忆身份。她是否在回答中提到“换了身体”，取决于人设和明确记录的迁移事件；硬件迁移本身不自动产生这种认知。

## 部署拓扑

公网只开放 TLS 网关所需的端口，手机使用 HTTPS，ESP32 使用 WSS。云端对话服务监听回环地址的 8000 / 8003，语音克隆服务只提供 `/run/rem-voice/tts.sock` 私有 Unix socket。

云端机器承担 API 调度、摘要记忆和 CPU 语音推理，没有在 2 核 4 GB 机器上运行 DeepSeek 模型本体。手机上的视觉推理不依赖电脑。外出需要 Wi-Fi 或热点；ESP32 的网络能力与手机不同，应分别实测。

## “专用系统”具体改了什么

以既有 Android / LineageOS 源码、内核和设备树为基础，增加 `rem_lavender` 产品，内置 RemBody 为 HOME，调整 Quickstep / Recents 的兼容性，修复 DTBO 和摄像头配置。没有从零重写安卓内核和驱动。

用户体验是手机开机进入角色。Android 内部仍把 Java 组件打包成 APK，作为系统组件构建；同包名、同签名的组件更新可以避免整套 ROM 重编。维护菜单仍保留设置和硬件检查，因此当前不是锁死所有系统入口的 kiosk。
